# grpo-math

> 用 GRPO 让一个未经微调的小模型自己学会做数学题 —— 不教解法，只告诉它答案对不对。

在 **Qwen2.5-1.5B Base** 上用 GRPO 做 GSM8K 数学推理后训练。
测试集准确率 **52.2% → 71.6%**（配对 McNemar 检验 *p* < 1e-13）。

这个仓库的重点不在那 19 个点，而在**怎么确认这 19 个点是真的**——
第一轮实验涨了 2.8 个点看起来很美，配对检验一做 *p*=0.32，是噪声。

## 核心结果

| 实验 | 准确率 | 格式合规 | vs 基线 | 判定 |
|---|---|---|---|---|
| 基线（未训练） | 0.522 | 0.852 | — | — |
| Stage 1（LoRA, lr=1e-6, 200 步） | 0.550 | 0.966 | +2.8 点，*p*=0.322 | ❌ **不显著** |
| **SFT only**（GSM8K 人工解答, 2 epoch） | 0.530 | **1.000** | +0.8 点，*p*=0.815 | ❌ **不显著** |
| Stage 2-A1（LoRA, lr=1e-5, 500 步） | **0.716** | 0.998 | +19.4 点，*p*=1.8e-14 | ✅ 极显著 |
| Stage 2-A2（全参, lr=2e-6, 500 步） | **0.720** | 0.996 | +19.8 点，*p*=1.3e-13 | ✅ 极显著 |
| Stage 2-B1（A1 + 自适应熵控制） | 0.700 | 0.998 | vs A1 −1.6 点，*p*=0.488 | ❌ 不显著 |
| Stage 2-B2（A1 换随机种子 43） | 0.708 | 0.996 | vs A1 −0.8 点，*p*=0.766 | ❌ 不显著（噪声地板） |
| **Stage 2-AC（SFT → GRPO, 500 步）** | 0.664 | 0.998 | **vs A1 −5.2 点，*p*=0.019** | ✅ **显著更差** |

### 四组核心对比

| 组合 | 准确率 | 相对基线 | 判定 |
|---|---|---|---|
| 基座（Qwen2.5-1.5B Base，未训练） | 52.2% | — | — |
| 基座 + **SFT** | 53.0% | +0.8 点，*p*=0.8148 | ❌ 不显著 |
| 基座 + **GRPO** | **71.6%** | +19.4 点，*p*<1e-13 | ✅ 极显著 |
| 基座 + **SFT + GRPO** | 66.4% | +14.2 点，*p*=1.5e-08 | ✅ 显著，但**低于纯 GRPO 5.2 点** |

**SFT 白做，GRPO 有效，SFT + GRPO 反而倒退。**

测试集为 GSM8K 全部 500 题，四组实验使用同一批题目、同一套奖励函数、同一随机种子。

**六个附带结论：**

1. **LoRA 不是瓶颈** —— LoRA(r=32) 与全参微调差 0.4 个点，小于单点标准误 2.2 个点，统计上不可区分。
2. **LoRA 容量也不是变量** —— SFT 分别用 2 个模块（17.4 MB）与 7 个模块（147.8 MB）训练，参数量差 8.5 倍，准确率 *p*=0.224 不可区分。
3. **后一半训练是白跑的** —— 全部收益在前 250 步取得。A1、A2、AC 三个独立设置一致（250→500 步增量 *p*=0.651 / 0.766 / 0.175），同等效果算力可减半。
4. **噪声地板已量化** —— 只换随机种子（B2）带来 −0.8 点、*p*=0.766，单点标准误 ±2.0–2.2 个百分点。**小于约 2–3 点的改进，本实验设计测不出来。**
5. **自适应熵控制无效** —— 目标熵 0.55，结果 −1.6 点、*p*=0.488，与单纯换种子的扰动无法区分。
6. **未观察到自我反思涌现** —— 反思词频在全部五个设置（基线 / Stage 1 / A1、A2 / SFT / AC）中都在 0.0%–1.4% 之间。在 1.5B 规模、500 步预算下，没有复现 R1-Zero 论文中的涌现现象。这是一个负结果，如实记录。

## 方法论：这个项目真正想展示的东西

### 1. 训练 reward 上涨 ≠ 模型变强

Stage 1 的训练曲线非常好看：reward 0.543 → 0.654，训练集正确率 0.401 → 0.495。
但测试集上准确率的提升 *p*=0.322，而**格式合规率**的提升 *p*=1.2e-9。

涨的几乎全是格式，不是推理能力。

这个诊断能成立，依赖一个设计决定：**三个奖励函数分开注册**，而不是合成一个总分。

```python
def make_reward_funcs(cfg):
    def r_format(completions, **kw): ...
    def r_answer(completions, gold=None, **kw): ...
    def r_length(completions, **kw): ...
    return [r_format, r_answer, r_length]
```

TRL 会按函数名分别记录 `rewards/r_format/mean`、`rewards/r_answer/mean`。
如果合成一个总分，这个关键发现就看不见了。

### 2. 只有配对检验能识破假信号

两次评测跑的是**同一批题目**，属于配对数据。直接比两个准确率会浪费掉配对结构。

```python
def mcnemar(a_flags, b_flags):
    b01 = sum(1 for x, y in zip(a_flags, b_flags) if not x and y)   # 由错变对
    b10 = sum(1 for x, y in zip(a_flags, b_flags) if x and not y)   # 由对变错
    chi2 = (abs(b01 - b10) - 1) ** 2 / (b01 + b10)                  # 连续性校正
    return erfc(sqrt(chi2 / 2))
```

Stage 1 的 52.2% → 55.0%，逐题看是 **93 道变对、79 道变错，净赚 14 道 / 500**。
McNemar 只看不一致对，统计效力远高于把两组当独立样本。

### 3. 从诊断到验证：单变量受控实验

Stage 1 效果不显著，可能是方法不行，也可能是训练太保守。
突破口是一个平时没人看的指标：**KL 全程 ≤ 0.001 —— 模型根本没有被推动。**

据此设计两组对照，**每组只改一个变量**，其余全部固定：

| 组 | 唯一改动 | 隔离的变量 |
|---|---|---|
| A1 | lr 1e-6 → 1e-5，200 → 500 步 | 学习率是否过小 |
| A2 | 关掉 LoRA 改全参，lr=2e-6，500 步 | LoRA 低秩约束是否限制容量 |

同一套代码、同一套奖励、同一批测试题，只改学习率和步数，
结果从「+2.8 点，*p*=0.32（噪声）」变成「**+19.4 点，*p*<1e-13**」。

诊断被证实。

### 4. 机制解释：熵曲线与准确率曲线的时间点吻合

```
A1 训练轨迹
  1–40 步    熵 0.670   ← 学习期
 81–120 步   熵 0.388
161–200 步   熵 0.288   ← 降到平台
241–280 步   熵 0.297   ← 之后一直横着
```

熵衡量输出多样性。**熵在 160–200 步降到平台，准确率提升也正好在那时停止。**
探索停止 → 学习停止。两条独立曲线的时间点吻合，构成完整的机制解释，
也解释了结论 2（后一半训练白跑）的成因。

### 5. 自定义诊断指标

TRL 自带的指标不够用，补了 GRPO 特有的两个：

```python
# 零方差组占比：一组 G 条回答全对或全错 → 组内 advantage 归零 → 这批采样白烧
groups = correct.reshape(-1, self.G)
zero_var = float(np.mean(groups.std(axis=1) < 1e-8))
```

**这里有一个定义差异值得注意**：TRL 自带的 `frac_reward_zero_std` 全程为 0，
因为它看的是**总奖励**的组内标准差（连续值，几乎不会恰好为 0）；
本仓库的 `diag/zero_var_group_ratio` 看的是**答案正确性**（二值，经常整组全对）。

衡量「采样是否被浪费」，后者才有意义。而这个指标在训练中**持续恶化：0.181 → 0.294**——
模型越强，一组回答全对的情况越多，advantage 归零，采样白烧。
目前已有约 29% 的采样被浪费，而采样占训练总时间的 60–80%。

这是下一阶段的题目，**动机来自本项目自己的实验数据，不是从论文里挑的**。

## 实验 A：SFT 冷启动的受控对照

对标「SFT 与 RL 如何协同」这一问题，设计四点对照：

```
基线 ：Qwen2.5-1.5B Base                      = 52.2%
S    ：Base → SFT(GSM8K 人工解答, 2 epoch)     = 53.0%
A1   ：Base ───────────→ GRPO(500 步)          = 71.6%
AC   ：Base → SFT ─────→ GRPO(500 步)          = 66.4%
```

> ⚠️ **本实验的冷启动是「短 CoT」，不是 R1 那种「长 CoT」冷启动，二者不可混为一谈。**
>
> |  | 冷启动数据 | 平均长度 | 反思词频 |
> |---|---|---|---|
> | DeepSeek-R1 | 长 CoT 数据（含反思、验证行为） | 长 | 有 |
> | **本实验** | **GSM8K 数据集自带的人工解答** | **51.7 词** | **0.0048** |
> | 基座自发输出（参照） | — | 164.7 token | 0.006 |
>
> 本实验的冷启动数据**比模型自身的输出还短**，且几乎不含反思。因此下文结论的准确表述是
> **「用比模型自发输出更简洁的数据做冷启动，会损害后续 RL」**，它与 R1「长 CoT 冷启动有效」
> 并不矛盾，反而从反面佐证了 R1 的选择：起作用的是冷启动数据的**风格**，而不是冷启动这一步本身。

除「是否经过 SFT」外全部固定：GRPO 超参、LoRA 配置（r=32, alpha=64, 7 个 target_modules）、
随机种子、奖励函数、测试集。SFT 采用合并进基座的方式，使 A1 与 AC 的 LoRA 结构完全同构
（合并已验算：不挂 LoRA 评测 = 0.530，与 base+adapter 一致）。

### 结论一：SFT 只改格式，不改能力

| | 变好 | 变差 | McNemar |
|---|---|---|---|
| **格式合规** 0.852 → 1.000 | **74 题** | **0 题** | *p* = 2.1e-17 ✅ |
| **答案正确率** 0.522 → 0.530 | 84 题 | 80 题 | *p* = 0.8148 ❌ |

500 道题的格式全部修对、**零退化**；推理能力则是几乎完美的随机游走。

这与 Stage 1（学习率过小的 GRPO）是**同一个特征的第二次出现**：

```
Stage 1（GRPO, lr 过小）：格式 p=1.2e-9   准确率 p=0.322
实验 A（SFT）           ：格式 p=4.1e-15  准确率 p=0.815
```

两种机制完全不同的方法产生同一签名，说明「格式涨、能力不动」是后训练中
**一类可复现的失效模式**，而非某次实验的偶然。识别它依赖三层分离奖励 + 配对显著性检验。

### 结论二：冷启动显著损害后续 RL

```
A1  (Base→GRPO)      71.6%
AC  (Base→SFT→GRPO)  66.4%      −5.2 个百分点，p = 0.019  ✅ 显著
```

−5.2 点超出本实验 ±2.0 点的噪声地板，是真效应。

**机制：四条独立证据指向同一解释 —— SFT 提前压低策略熵并固化简洁风格，
压缩了 RL 所需的探索空间。**

| 证据 | 数据 |
|---|---|
| 熵被提前压死 | A1 由 0.670 起步、160 步后坍缩到 0.29；SFT 终点熵 0.384，AC 全程 0.25–0.36，**从未有过探索期** |
| 风格被固化，RL 逆转不了 | `stepwise` 基线 0.520 → SFT 0.016 → AC 仅恢复到 0.028（A1 为 0.484） |
| 输出长度同样回不去 | 基线 164.7 → SFT 99.3 → AC 仅恢复到 114.6 token（A1 为 171.2） |
| 采样浪费加剧 | 零方差组占比：A1 最终 0.294，AC 训练期 0.25–0.50 |

### 结论三：这个负结果本身有判据价值

它不是「冷启动没用」，而是给出**什么时候不该做冷启动**：

> 当任务的奖励可验证、且 SFT 数据的风格比模型自发行为更简短时，
> 冷启动会提前压低策略熵、固化不利于推理的输出风格，从而损害后续 RL。

这也解释了为何 R1 使用**长 CoT** 数据做冷启动，而非数据集原生的简洁解答 ——
真正起作用的可能不是「有没有冷启动」，而是**冷启动数据的风格是否包含目标行为**。
佐证：本项目 SFT 数据（GSM8K 人工解答）的 `reflection` 词频仅 0.0048，
模型自然学不到数据里不存在的行为。

## Stage 2-D：训推一致性的直接测量

### 问题

GRPO 训练中，同一批 token 被两个引擎处理：采样端 vLLM 生成并给出 logprob，
训练端 transformers 重新前向再算一次。理论上应当一致，实际不然。
TRL 日志里 `sampling/importance_sampling_ratio` 的实测范围是 **0.013 – 2.69**（理想值 1），
偏离远超预期。

策略梯度假定「更新的策略就是产生样本的策略」。偏离 1 意味着未经校正的 off-policy
更新 —— 梯度有偏。这正是 TIS（截断重要性采样）与 Off-policy Masking 要解决的问题。

### 测量方法

关键是**固定 token 序列**：先生成一次并存下 token，之后所有打分都用同一串。
否则比较的就不是数值路径，而是「生成了不同的东西」。

```
① 用合并模型生成一次，固定 token（并保存生成路径的 logprob）
② vLLM 挂 LoRA   → teacher-forcing 打分
③ vLLM 合并权重  → teacher-forcing 打分
④ HF   挂 LoRA   → 打分
⑤ HF   合并权重  → 打分
```

每阶段独立进程（vLLM 与 HF 不能同时占显存），按**产物文件**而非退出码判定成败
—— vLLM 常在清理阶段 abort，但那时数据已写盘。

### 四个假设的检验

| 假设 | 结果 | 数据 |
|---|---|---|
| ① vLLM 的 LoRA 算子路径与 PEFT 实现不同 | ❌ **证伪** | 挂 LoRA 0.01500 vs 合并权重 0.01456，**1.03 倍** |
| ② 增量解码（生成路径）与 teacher-forcing 不同 | ❌ **证伪** | 生成路径 0.01497 vs TF 0.01456，**1.03 倍** |
| ③ 低概率 token 的数值敏感度更高（温度决定其占比） | ✅ **成立** | 贪心 0.00852 → T=1.0 0.01456，**+72%** |
| ④ 训练期策略更发散（熵高 → 低概率 token 多） | ❌ **证伪** | A1 熵 0.560→0.307（−45%），偏差 0.0191→0.0213（**+11%**） |

### 核心发现：偏差与 token 概率强单调相关

T=1.0、35104 个 token，按 vLLM 给出的 token 概率分层：

| token 概率 | 数量 | 占比 | \|Δlogp\| 均值 | 偏离 >20% |
|---|---|---|---|---|
| ≥0.99 | 19807 | 56.4% | 0.00231 | 0.06% |
| 0.90–0.99 | 5357 | 15.3% | 0.00466 | 0.09% |
| 0.70–0.90 | 3370 | 9.6% | 0.01737 | 0.15% |
| 0.50–0.70 | 1926 | 5.5% | 0.03184 | 0.83% |
| 0.20–0.50 | 2420 | 6.9% | 0.04972 | 1.49% |
| 0.05–0.20 | 1344 | 3.8% | 0.07145 | 5.51% |
| 0.01–0.05 | 524 | 1.5% | 0.08168 | 7.44% |
| <0.01 | 276 | 0.8% | 0.09914 | **8.70%** |

**跨越 43 倍的单调关系**；偏离 >20% 的比例跨越 145 倍。

同时：**偏差不随生成推进而累积**（按位置五等分，0.0110 / 0.0076 / 0.0079 / 0.0082 / 0.0080，基本平坦）。

### 跨运行观察

| 运行 | 熵范围 | \|Δlogp\| 范围 |
|---|---|---|
| A2（全参） | 0.23–0.36 | 0.0075–0.0101 |
| B2 | 0.29–0.50 | 0.0175–0.0213 |
| A1（LoRA） | 0.30–0.56 | 0.0191–0.0225 |
| AC（冷启动） | 0.28–0.48 | 0.0180–0.0330 |
| B1（熵控制） | 0.57–0.60 | 0.0187–**0.0325** |

跨运行看，熵低则偏差低。**A1 与 A2 在训练日志上 2.5 倍的差距，来自熵的不同而非 LoRA
（假设 ① 已证伪）。** 副产品：B1 的熵控制虽未提升准确率，却让训推偏差持续恶化到五组最高。

### 尚未解释的残余

```
静态测量（A1 最终权重、T=1.0、生成路径）  0.01497
A1 训练日志末 100 步均值                  0.02127     ← 仍高 42%
```

同权重、同温度、同路径，训练报告值仍显著更高。最可能是 TRL 对该指标的**聚合口径**
与本测量不同（例如先按序列平均再平均），属定义差异而非物理差异。未进一步追查。

### 结论与判据

1. 训推不一致真实存在、可测量、机制清楚：**集中在低概率 token 上**
2. **受影响的 token 不足 1%**（T=1.0 下偏离 >20% 者占 0.73%）
3. **A1 与 A2 最终准确率统计不可区分**，尽管训练日志报的偏差相差 2.5 倍

> **判据：在本规模（1.5B / GSM8K）下，一刀切按 ratio 截断（TIS）会系统性误伤
> 大量正常的低概率 token —— 而那些位置恰恰是探索的来源。不建议在此规模上启用；
> 更适合作为诊断指标而非修正手段。**

若要做修正，应当分层：按 token 概率设不同容忍阈值，或专门识别「vLLM 认为概率≈1
而训练端认为极低」的极端失配（贪心测量中共 4 例，最极端者 logprob 差 14.6，
即概率差约 220 万倍），那一类与温度无关，才是真正的异常。

## 技术栈

**TRL**（GRPO）+ **PEFT/LoRA**（省显存）+ **vLLM**（加速采样）+ **transformers**

双卡分工：一张卡专职 vLLM 采样，另一张专职训练。

## 下一阶段

围绕「RL 训练稳定性与训推一致性」展开：

- **训推一致性测量** —— 采样引擎（vLLM）返回的 logprob 与训练侧重算的 logprob 存在差异，
  破坏 GRPO 的 on-policy 假设。**TRL 1.13 已内置该度量**，实测
  `sampling/importance_sampling_ratio` 的范围为 0.013 – 2.69（理想值为 1），
  `sampling_logp_difference` 均值 0.033、最大 1.504 —— 偏离程度远超预期，值得深入。
- **重要性采样修正** —— truncated importance sampling / off-policy masking 的单变量对照。
- **采样预算分配** —— 针对零方差组占比 0.18 → 0.29 的持续恶化。
- **熵坍缩抑制** —— 熵在 160 步降到平台后学习停止。

## 踩过的坑

| 问题 | 根因 | 解决 |
|---|---|---|
| `hf download` 401 | 新版 huggingface_hub 走 Xet CAS，镜像站不代理 | `HF_HUB_DISABLE_XET=1` |
| `GRPOConfig` 报 `max_prompt_length` 非法 | TRL 1.13 已移除该字段 | 删除 |
| `GRPOConfig` 报 `logging_dir` 非法 | GRPOConfig 并非完整继承 `TrainingArguments` | 删除，TB 默认写 `output_dir/runs/` |
| `TensorBoardCallback requires tensorboard` | vLLM 和 TRL 都不依赖它 | `pip install tensorboard` |
| `SFTConfig` 不接受 `warmup_ratio` | TRL 1.13 的 SFTConfig 与 GRPOConfig 一样并非完整继承 `TrainingArguments`，133 个字段里只有 `warmup_steps` | 改用 `warmup_steps` |
| vLLM 启动 `Free memory … less than desired` | `gpu_memory_utilization: 0.80` 按空卡设定；共享机器上他人占 20GB 后，需求 66.5GiB > 可用 62.9GiB | 降到 0.45；1.5B 用不到那么多 KV cache |
| patch 脚本报「锚点未找到」，但配置其实已改 | **重试循环里放了非幂等操作**：首次成功后连接断开，重试时锚点已消失 | 改成「已是目标值则跳过」的幂等写法 |
| vLLM 阶段「失败」但数据已写盘 | 引擎清理与 Python 解释器终结竞争 GIL，工作完成后在退出阶段 abort；`set -e` 据退出码误判 | 收尾 `os._exit(0)` 绕过 finalization；驱动脚本按**产物文件**判定成败 |
| SFT 的 LoRA 与 A1 不可比 | `train_sft.py` 未传 `target_modules`，PEFT 对 Qwen2 默认只挂 q/v 两个模块（17.4MB），而 A1 挂 7 个（147.8MB），参数差 8.5 倍 | 配置补全并**在日志中打印实际挂载的模块** |

**方法论教训**：前三次是一个参数一个参数试错。第四次改成**一次性把 28 个参数
对着 `dataclasses.fields()` 的 189 个真实字段全量核验**，一次通过。
